## 中文

实时监听**系统正在播放的声音**（视频、网课、线上会议）、**麦克风**（讲座、会议、对话），或两者同时，在本机识别成文字，交给你选择的大模型翻译，以**悬浮双语字幕**显示在屏幕上，并自动保存文字记录、导出 SRT / WebVTT 字幕。听的过程中可以随时向 **AI 助手**提问，结束后可以把字幕整理成**笔记**。

| 环节 | 实现 | 说明 |
|---|---|---|
| 系统声音 | WASAPI 环回采集（NAudio） | 不需要虚拟声卡 |
| 麦克风 | WASAPI 采集（NAudio） | 默认录音设备变化时自动重新开始采集；可选降噪（Windows 通话语音处理） |
| 语音识别 | Whisper.net（whisper.cpp），本地运行 | 首次使用时下载模型；音频不离开本机 |
| 翻译 | Google 翻译（默认）、下载到本机的混元翻译、Claude Code 命令行，或模型服务（默认列出 OpenAI、通义千问、DeepSeek、Kimi、Grok，也可以添加 Anthropic、OpenAI 兼容接口、本机的 Ollama / LM Studio） | 随时切换 |
| 界面 | WPF 悬浮字幕 + 托盘图标 | 置顶、不抢焦点、可锁定为点击穿透；外观跟随系统 / 浅色 / 深色 |
| 录音 | Media Foundation AAC（Windows 自带） | 可选，把听到的声音存成 .m4a，和字幕记录放在一起 |

### 运行要求

- Windows 10 或 Windows 11，64 位（x64）。
- [.NET 10 桌面运行时](https://dotnet.microsoft.com/download/dotnet/10.0)（x64 的 “.NET Desktop Runtime”）；使用“独立发布”构建时不需要安装。
- 处理器：识别在处理器上运行。支持 AVX2 的处理器更快；base 模型在近几年的笔记本上可以跟上正常语速。
- 首次使用需要联网下载识别模型（tiny 约 75 MB，base 约 142 MB，small 约 466 MB）。
- 翻译默认用 Google 翻译，不需要账号和设置（需要联网）。也可以换成：
  - 混元翻译：在“模型服务”里下载（约 1.2 GB，运行时占用约 1.4 GB 内存），在本机离线翻译；
  - 已登录的 Claude Code 命令行；
  - 自己的 API 密钥：默认列出的 OpenAI、通义千问、DeepSeek、Kimi、Grok，或者自己添加的 Anthropic、Gemini、OpenRouter 等；
  - 本机运行的 Ollama / LM Studio。
- AI 助手、生成笔记和自动纠正口音需要大模型（Claude Code、模型服务）；Google 翻译、混元翻译只能翻译。

### 构建与运行

需要 [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0)。在 `windows` 目录下：

```powershell
dotnet build LiveSub.Windows.sln -c Release          # 构建
dotnet test tests/LiveSub.Core.Tests                 # 单元测试（不依赖 Windows，macOS 上也能跑）
dotnet run --project src/LiveSub.App -c Release      # 运行

# 独立发布：目标电脑不需要安装 .NET，输出 publish\LiveSub.exe
dotnet publish src/LiveSub.App -c Release -r win-x64 --self-contained -o publish

# 可选：带 Vulkan 显卡运行库（体积更大；设置里打开“显卡加速”）
dotnet publish src/LiveSub.App -c Release -r win-x64 --self-contained -p:LiveSubGpu=vulkan -o publish-vulkan
# NVIDIA 显卡也可以用 -p:LiveSubGpu=cuda（需要本机安装对应的 CUDA 运行库）
```

程序没有代码签名，第一次运行时 SmartScreen 可能提示“未知发布者”，选择“仍要运行”。

开发时在 macOS 上也能构建（`EnableWindowsTargeting`），但不能运行界面。

### 首次使用

1. 运行 `LiveSub.exe`。任务栏右侧的通知区域出现字幕图标（可能在“^”折叠区里，可以拖到任务栏上），屏幕右上角出现字幕面板，中间是“开始翻译”按钮。新用户的音源是“两者”（麦克风和系统音频同时识别），可以在快捷按钮的音源菜单或设置里改。
2. 翻译模型默认是 Google 翻译，不需要设置。想换模型时，点字幕上的设置按钮（或右键托盘图标 → **设置…**），在“翻译模型”里选择：用 Claude Code 不需要别的设置；用默认列出的 OpenAI、通义千问等服务时，在“模型服务”一行点 **管理…** 填上 API 密钥，点 **测试** 确认可用；混元翻译要先在“模型服务”里下载（见下一节）。
3. 点字幕中间的 **开始翻译**（或右键托盘图标 → **开始字幕**）。第一次会下载识别模型，“开始翻译”按钮下面显示下载进度；模型保存在 `%LOCALAPPDATA%\LiveSub\models`。
   无法访问 huggingface.co 时，在设置 → 识别 → **模型下载地址** 填镜像站（例如 `https://hf-mirror.com`），或者手动把 `ggml-base.bin` 放进上面的文件夹。

### 翻译模型与模型服务

与 macOS 版相同：设置里的“翻译模型”分为三组，托盘菜单和状态条（点模型名）里也能切换，最后一项都是“管理模型服务…”。

- **基础**：Google 翻译（新用户的默认选择；之前用过的用户保留原来的选择）。
- **云端模型**：Claude，以及每个云端模型服务。
- **本地模型**：混元翻译（下载到本机），以及本机或局域网里的服务（Ollama、LM Studio 等）。

**每家服务只列一项**（菜单里写“Claude”“通义千问”这样的服务名），具体用哪个模型在“模型服务”里为翻译和 AI 助手分别选：每家都有“翻译用”“AI 助手用”两个选择。Claude 默认翻译用 Haiku、AI 助手用 Sonnet。在“模型服务”里改了某家的“翻译用”，正在用这家的翻译跟着换；AI 助手同理。日志、状态和笔记进度里写完整名称，例如“Claude · Haiku”“通义千问 · qwen-flash”“混元翻译 · Hy-MT2 1.8B”。

从之前的版本升级：以前在列表里直接选过的具体模型（例如 Claude Opus，或某个服务的某个模型）会记成 Claude 的“翻译用”或这家服务的“翻译用”“AI 助手用”，接着用原来的模型。

**Google 翻译**（免费网页接口，不需要密钥）

- 与 macOS 版相同：两个接口（`translate.googleapis.com` 的 gtx 和 `clients5.google.com` 的 dict-chrome-ex）轮换。一个被限流（HTTP 429 或服务器出错）时换另一个，被限流的冷却 60 秒；两个都不行就等 1–4 秒再各试一次，还不行才算这句失败。
- 每句单独翻译，不带上下文（macOS 实测带上下文几乎没有区别）。Google 翻译和混元翻译同时翻两句，后一句不用等前一句；大模型带着上下文，按顺序一句一句翻。
- 测试用：环境变量 `LIVESUB_DEBUG_GOOGLE_FAIL=gtx`（或 `dictionaryExtension`、`all`）假装这个接口被限流。

**混元翻译**（腾讯混元 Hy-MT2 1.8B，在本机离线翻译）

- 在“模型服务”的“混元翻译 · 本机”一栏点 **下载**：先下载 llama.cpp 运行程序（固定版本 b11829；x64 用 Vulkan 版 `llama-b11829-bin-win-vulkan-x64.zip`，约 37 MB，可以用显卡，也带处理器后端；ARM64 用 `llama-b11829-bin-win-cpu-arm64.zip`，约 13 MB），再下载模型 `Hy-MT2-1.8B-Q4_K_M.gguf`（1 133 080 448 字节）。都按 SHA-256 校验，不对就删掉并报错；可以取消，失败后可以重试。模型的下载顺序：设置 › 识别 › 模型下载地址（填了的话）、Hugging Face、hf-mirror.com。
- 文件在 `%LOCALAPPDATA%\LiveSub\LocalModel\`；“删除”删掉整个文件夹，正在用混元翻译时换回 Google 翻译。
- 翻译时在后台启动 `llama-server`（不弹出窗口，只监听 127.0.0.1 上随机的空闲端口，参数与 macOS 相同：`-c 4096 -np 2 --jinja --no-webui -ngl 99`；设置里关闭“显卡加速”时 `-ngl 0`），加载模型最多等 90 秒。没有翻译器在用或闲置 10 分钟后关掉，退出程序时关掉；程序崩溃时由 Windows 作业对象（与 claude 进程相同）跟着结束，不会在后台一直占着内存。输出写在 `%LOCALAPPDATA%\LiveSub\logs\llama-server.log`。
- 提示词、采样参数（temperature 0.7、top_p 0.6、top_k 20、repeat_penalty 1.05）与 macOS 相同；每句带上前两句原文作背景。“测试”的用时不算启动服务、加载模型的时间。
- 选了混元翻译但还没下载就开始字幕：字幕上提示“混元翻译还没有下载，先用 Google 翻译。请在“模型服务”里下载。”，打开“模型服务”并滚到这一栏，这次先用 Google 翻译；下载完成后，正在运行的字幕换成混元翻译。
- llama-server 需要 Microsoft Visual C++ 运行库（识别用的 Whisper 也需要，一般已经装好）；缺少时提示安装。

**Claude Code 命令行**（用你的 Claude Code 登录额度，与 macOS 版相同）

1. 安装 Claude Code（PowerShell 运行 `irm https://claude.ai/install.ps1 | iex`，或 `npm install -g @anthropic-ai/claude-code`）。
2. 在终端运行 `claude`，输入 `/login` 登录一次。
3. 在“模型服务”的“Claude Code”一栏选“翻译用”“AI 助手用”的型号：Haiku（最快）、Sonnet（均衡）或 Opus（最准确、最慢）。**Claude 路径**也在这一栏（原来在设置里），留空时自动查找：PATH、`%USERPROFILE%\.local\bin\claude.exe`、`%APPDATA%\npm\claude.cmd`（npm 安装的会改用 node 直接运行，以便传递多行提示词）。点 **测试** 用“翻译用”的型号翻译一句话。
4. 程序保持一个长驻的 `claude -p --input-format stream-json …` 进程，参数与环境变量与 macOS 版一致；每 40 句换新进程，新进程第一句带最近 6 句作为上下文。

**模型服务**（自己的 API 或本地模型）

设置 → 模型服务 → **管理…**（托盘菜单和状态条的模型菜单里也有“管理模型服务…”）。窗口里依次是 Claude Code、混元翻译和各个服务。

- **默认列出的服务**：OpenAI（gpt-5.4-mini）、通义千问（qwen-flash）、DeepSeek（deepseek-flash）、Kimi（kimi-k2.6）、Grok（grok-4.20-0309-non-reasoning），已经在翻译模型和 AI 助手里，填上自己的 API 密钥就能用。服务的 Id 与 macOS 相同，每次启动补上缺的；删掉的不再补（可以从“添加模型服务”里再加回来）；自己加过同一地址的服务时也不补。选了还没填密钥的服务时，会打开“模型服务”并滚到这家，提示去填密钥。
- 每个服务：名称、接口格式、接口地址、API 密钥、**可用模型**（点 **获取列表** 取得模型后删去不需要的，多个模型用逗号分隔）、**翻译用**、**AI 助手用**、**测试**（用“翻译用”的模型翻译一句话，显示“X 可用，用时 N 秒：译文”）和删除。删除服务时密钥一并删除，正在用它的翻译模型换回 Google 翻译，AI 助手换回 Claude。
- 关掉思考：DeepSeek、Kimi（只有 kimi-k2.6 能关）的请求带 `thinking: {type: disabled}`，通义千问带 `enable_thinking: false`，别的服务一律不带（OpenAI 收到不认识的参数会返回 400）。

| 模板 | 接口格式 | 接口地址 | 密钥 |
|---|---|---|---|
| OpenAI（默认列出） | OpenAI 兼容 | `https://api.openai.com/v1` | 需要 |
| 通义千问（默认列出） | OpenAI 兼容 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | 需要 |
| DeepSeek（默认列出） | OpenAI 兼容 | `https://api.deepseek.com` | 需要 |
| Kimi（默认列出） | OpenAI 兼容 | `https://api.moonshot.cn/v1` | 需要 |
| Grok（默认列出） | OpenAI 兼容 | `https://api.x.ai/v1` | 需要 |
| Anthropic | Anthropic | `https://api.anthropic.com` | 需要 |
| Gemini（OpenAI 兼容接口） | OpenAI 兼容 | `https://generativelanguage.googleapis.com/v1beta/openai` | 需要 |
| OpenRouter | OpenAI 兼容 | `https://openrouter.ai/api/v1` | 需要 |
| Ollama | OpenAI 兼容 | `http://localhost:11434/v1` | 不需要 |
| LM Studio | OpenAI 兼容 | `http://localhost:1234/v1` | 不需要 |
| 自定义 | 任选 | 任意兼容的地址 | 本机和局域网地址不需要 |

- OpenAI 兼容：`POST {接口地址}/chat/completions`，流式输出；模型列表来自 `GET {接口地址}/models`。推理模型（例如 DeepSeek R1）的思考内容不会显示，但会增加延迟，翻译建议选非推理模型。
- Anthropic：官方 C# SDK，`POST {接口地址}/v1/messages`；模型列表来自 `GET {接口地址}/v1/models`。低延迟设置：Haiku 关闭思考；Sonnet 与 Opus 不能关闭思考，改为 effort = low；模型名不是 `claude-` 开头时不加这些参数。
- 从 Windows 0.1 升级：原来的 Anthropic API 设置变成名为“Anthropic”的模型服务，原来的 OpenAI 兼容服务变成同名的模型服务，密钥和所选模型都保留。

所有大模型都使用与 macOS 版相同的提示词、上下文格式（`[Context]…[Translate]`）和译文清理规则。分句与 macOS 相同：没有句末标点的长句超过 24 个单位（英文按单词，中日韩每 2 个字算 1 个）就在逗号等从句边界切开，停顿时送出的剩余内容太长也同样切开。

### 使用

- **悬浮字幕**（改过）：新用户的字幕在屏幕右上角，面积是屏幕的 1/16、宽高比 3:1（与 macOS 相同；之前用过的用户保留自己的大小和位置）。没开始时字幕中间是醒目的 **开始翻译** 按钮，下面一行是音源和语言（上次出错时是原因，准备中时是下载识别模型的进度）；已有字幕时上次的字幕压暗。按住字幕拖动。窗口大小只随设置变化，出字幕时不会忽高忽低：新字幕在框里从下往上滚动。拖左右边框改宽度；拖上下边框改成自己想要的高度；双击上下边框恢复按“显示最近 N 句”算的高度（每句按一行原文、一行译文算，再加下面“正在说”的一行）。改字号等设置让窗口变高时底边不动、向上生长，超出屏幕时推回屏幕内。在字幕上往上滚动可以翻看之前的字幕，这时右边出现细的位置条和“返回实时”；停在底部时自动跟随最新一句。
  - **快捷按钮**（改过，与 macOS 相同）：鼠标移到字幕上，右上角出现七个按钮：开始/停止、录音、锁定、音源（菜单：麦克风 / 系统音频 / 麦克风和系统音频，当前的打勾）、AI 助手（打开着时变黄，浅色外观下为橙色）、设置、退出。鼠标停在按钮上**立刻**在下面显示按钮的名字（不用等系统提示），名字随状态变（开始 → 停止、录音 → 停止录音）。字幕一直在最上层，没有“置顶”开关。原来的“⋯”菜单和“收起”按钮去掉了：显示内容在设置里，字幕记录在设置 › 记录 和托盘菜单里，收起字幕用快捷键或托盘菜单；“字幕移回屏幕底部”并进了设置里的“恢复默认”。
  - **正在说**：还没分好句的内容显示在字幕下方固定的一行里（斜体、较淡）。超过一行时只显示最新的部分，前面是“…”，有空格的语言不会从单词中间截断。没有内容时这一行也留着，上面的字幕不会跳动。音源为“两者”、两边同时在说时是两行，各带音源标签；窗口高度不变，上面的字幕区让出一行。
- **外观**（新，设置 › 字幕 › 外观）：跟随系统（默认）、浅色、深色，与 macOS 相同。深色是黑底白字，浅色是白底黑字（加一圈很淡的描边），字幕、AI 助手、设置、模型服务、字幕记录、录音记录窗口一起变。“跟随系统”看的是 Windows 的“设置 › 个性化 › 颜色 › 选择默认应用模式”，改了马上跟着变。设置类窗口用 WPF 自带的 Windows 11 风格主题（Fluent）；弹出菜单和托盘菜单仍是系统的浅色样式。
- **录音**（新，与 macOS 相同）：点快捷按钮里的录音按钮（或托盘菜单的“录音”），字幕运行期间把听到的声音存进记录文件夹，文件名由字幕记录的文件名把“字幕记录”换成“录音”，例如 `2026-10-22 13.35 录音.m4a`（英文界面为 `… Recording.m4a`）；音源为“两者”时每路一个文件，后面带音源，例如 `… 录音（麦克风）.m4a`；重名时加序号，不覆盖。运行中途可以随时打开或关掉；没在运行时点它只记下设置，下次开始时录。录音时按钮变红，状态条上有红色的“录音”。格式是 AAC（.m4a），用 Windows 自带的 Media Foundation 编码器，48 kHz 单声道，约 96 kbps（Windows 的 AAC 编码器最低 96 kbps，macOS 是 64 kbps），一小时约 43 MB。录下的声音和真实时间对齐（系统没有声音时补静音）。设备切换、采集中断后重新打开时接着录进同一个文件；改设置引起的自动重启会另开一个文件。
- **录音记录**（新，设置 › 记录 › 录音记录 › 查看…，或托盘菜单）：列出记录文件夹里的录音，最新的在上面，每个显示时长和大小；有同一次的字幕记录时有“字幕记录”按钮（用默认程序打开），“播放”用默认的播放器打开，文件夹按钮在资源管理器中选中它。底部是“共 N 个录音”、“打开记录文件夹”和“刷新”；窗口回到前面时自动重新读一遍。
- **托盘图标**（改过）：macOS 去掉了菜单栏图标，Windows 上托盘图标是常规做法，保留，菜单和快捷按钮对齐。字幕收起时，左键单击把字幕（和打开着的 AI 助手）显示出来；字幕显示着时，左键单击和右键一样打开菜单。菜单顺序：
  - 状态（麦克风权限被关闭时下面还有“打开麦克风设置”）；
  - 开始字幕 / 停止字幕、录音（打勾表示打开）、音源、翻译模型（最后一项是“管理模型服务…”）；
  - 收起字幕 / 显示字幕（右边是快捷键）、锁定字幕、AI 助手；
  - 字幕记录…、录音记录…；
  - 设置…、退出。

  导出字幕、开始新的记录、生成笔记、打开记录文件夹挪到了“字幕记录”窗口，显示内容在设置里（与 macOS 相同）。字幕收起时从菜单点“开始字幕”，字幕会显示出来。图标实心表示正在听。
- **设置**（改过，与 macOS 相同）：去掉了可折叠的“更多”，全部直接列出。行尾不放说明文字，说明在鼠标停上去的提示里。
  - **翻译**：语言、音源（麦克风 / 系统音频 / 两者）、麦克风降噪（音源不是“系统音频”时出现）、翻译模型（分组和服务名见上一节）、模型服务（“已设置 N 个”只算本地服务和填了密钥的服务）、**过滤周围的中文交谈**（原来叫“过滤中文说话声”）、自动纠正口音、纠正时保留识别原文（打开自动纠正后出现）。
  - **字幕**：显示内容、外观、字号（一个滑块同时调译文和原文）、背景、显示最近 N 句（拖过上下边框后隐藏）、大小（只有“恢复默认”按钮，鼠标停上去的说明是“拖动字幕边框可以调整大小。点这里让字幕恢复默认大小，移回屏幕右上角；AI 助手回到字幕旁边。”）、显示状态条、锁定字幕、快捷键。
  - **记录**：字幕记录（查看…）、录音记录（查看…）、记录文件夹。
  - **识别**（Windows 版特有）：识别模型、显卡加速、实时预览、模型下载地址。

  Claude 路径在“模型服务”的 Claude Code 一栏。设置、模型服务窗口只有关闭按钮，没有最小化、最大化。用 LiveSub 时（前台是本程序的窗口）设置、模型服务、字幕记录、录音记录窗口显示在字幕和 AI 助手上面；切到别的程序时回到普通层，不挡别人。在托盘菜单或字幕上改了设置，打开着的设置窗口会跟着变。
- **快捷键 Win+Alt+L**（默认）：显示或隐藏字幕。可在设置 → 字幕 → 快捷键 改成 Ctrl+Alt+L 或关闭。默认不用 Ctrl+Alt+L，是因为波兰语等键盘布局里 Ctrl+Alt 等同于 AltGr，会占用 AltGr+L 输入的字符（如“ł”）。
- **锁定字幕**：字幕不再响应鼠标，可以点到下面的窗口。快捷按钮里的锁在没锁定时是开口的；锁定后鼠标移到字幕上，右上角出现一把闭合的锁，点它解锁，字幕的其他地方仍然点不到。也可以在托盘菜单里解锁。
- **音源“两者”**（设置里的“两者”，托盘菜单和快捷按钮的音源菜单里的“麦克风和系统音频”；改过：新用户的默认音源）：与 macOS 版相同，同时识别麦克风和系统正在播放的声音，例如线上会议里自己说的和对方说的。
  - 每句原文前面有小标签“麦克风”或“系统音频”；“正在说”每个音源一行，也带标签。字幕记录窗口里标签在时间后面，记录文件里写成 `**[时间] 麦克风** 原文`。只用一个音源时没有标签。
  - 两路共用一个识别模型，语音段按先后识别；翻译跟不上时只合并同一音源的积压句子。状态条的音量取两路中较大的，两路都没有声音时才显示“无音频输入”。
  - 默认输出设备变了只重新开始系统音频，默认录音设备变了只重新开始麦克风。开始时一路打不开、中途断开或新设备打不开时，另一路照常工作，那一路每隔几秒重新打开；两路都打不开才算启动失败。
  - 外放声音时麦克风会把扬声器的声音再录一遍，可能出现重复的字幕：戴耳机，或打开“麦克风降噪”（含回声消除）。
- **麦克风降噪**（设置 → 翻译，音源为“麦克风”或“两者”时出现，默认关闭）：用 Windows 的通话语音处理打开麦克风，降低环境噪音并消除回声（与 macOS 版的系统语音处理相对应）。具体效果取决于声卡驱动，较新的 Windows 11 上还有“语音清晰度”。讲者离麦克风较远时可能反而降低识别效果。程序会让 Windows 不因此调低其他声音的音量；驱动不支持时照常录音，日志里有 `audio: noise reduction unavailable`。
- **麦克风权限**：Windows 隐私设置关闭了麦克风时，字幕不会停止，字幕下方提示去哪里打开，并有“打开麦克风设置”按钮；字幕锁定时托盘菜单里也有这一项。打开权限后几秒内自动继续。音源为“两者”时只有麦克风这一路等待，系统音频照常识别。
- **状态条**（字幕底部一小行；改过）：音量、识别是否清晰、录音中（红色的“录音”）、当前翻译模型的服务名（Google 翻译、混元翻译在纠正期间显示“Claude · 纠正中”）、待翻译句数、最近的错误。鼠标移到翻译模型上，文字变蓝、底下出现淡淡的胶囊；点开是模型菜单（“基础”“云端模型”“本地模型”三组、只写服务名、当前的打勾），最后一项是“管理模型服务…”。
- **自动纠正口音**（设置 → 翻译，默认关闭）：讲者口音重、识别不准时，让大模型按发音和上下文纠正识别错误，状态条显示“识别较难 · 已自动纠正”。用 Google 翻译、混元翻译时，纠正期间临时改用 Claude Sonnet（需要本机已登录 Claude Code，没有时状态条的提示会说明），识别清楚了换回原来的翻译；Claude 出错时这一句先用原来的翻译。关闭时只在状态条上显示“识别较难”，不改原文，也不换翻译会话。打开后下面出现“纠正时保留识别原文”，选中时记录里同时保留识别器原来的文字。
- **AI 助手**（字幕上的 AI 助手按钮，或托盘菜单 → AI 助手）：边听边提问，与 macOS 版相同。
  - 助手可以读取本次点“开始”以来的全部字幕。提问时才把上次提问以来新增的字幕和正在说的半句一起发给模型，不会每句都发。
  - 标题栏里选回答用的模型：云端模型和本地模型两组（没有只能翻译的 Google 翻译、混元翻译），每家服务一项，具体模型是这家的“AI 助手用”，默认 Claude（Sonnet）；换模型后，下一问会把全部字幕重新带上。鼠标移到模型名上文字变蓝，关掉菜单后复原（改过）。“新对话”清空问答；点“开始”和“开始新的记录”时也会开始新的对话，改设置引起的自动重启不会。
  - 标题栏和输入栏的按钮（模型、新对话、收起、回形针、发送），鼠标停上去**立刻**显示说明（改过，不用系统提示的延迟）。
  - **附件**（新，与 macOS 相同）：提问可以带图片和文件，四种入口：粘贴图片（截图、网页上复制的图片）、粘贴资源管理器里复制的文件、拖进面板（拖动时面板出现蓝色描边）、点输入框左边的回形针选择（可以多选）。附件显示在输入框上方，点 × 去掉；读取时转圈，读完才能发送；读不了的文件在这里用橙色说明。一次最多 10 个。只带附件、不写问题也能发送（替你问“请看附件。”）。提问气泡下面列出带的附件名。
    - 图片：长边缩到 1568 像素，按照片的方向信息转正；有透明部分的存 PNG（超过 3.5 MB 改 JPEG），其余存 JPEG。
    - PDF：给 Claude Code 和 Anthropic 格式的服务发原文件（Claude 连图表一起看；超过 20 MB 或 100 页时只发文字）；给 OpenAI 兼容格式的服务发提取出的文字（用 PdfPig 提取，扫描件没有文字时会说明）。
    - Word（.docx）、OpenDocument（.odt）、RTF 读出文字；纯文本、代码、字幕文件等按文本读（UTF-8，不是 UTF-8 时按系统的旧编码，例如 GBK）。旧的 .doc、PowerPoint 等提示“暂不支持这种文件，可以存成 PDF 或图片再添加”。文字超过 20 万字时只附上前面一部分。单个文件最大 50 MB。
    - Claude Code 的 stream-json 输入里图片、文档块和 Anthropic API 格式一样；附件留在这次对话的历史里，追问时模型还看得到。
  - 下方是“总结最近的内容”“解释相关概念”“解释上一句”三个快捷问题；输入框按回车发送。回答支持粗体、斜体和行内代码，可以选中复制。
  - **存成文件**：在对话里说“把总结存成文件”“把要点整理到文件夹里”之类的话，助手会把内容写成 Markdown 文件，保存在记录文件夹下的“AI 助手”文件夹里（默认 `文档\LiveSub\AI 助手\`，英文界面下文件夹名为 `AI Assistant`；记录文件夹写不进去时放在 `%LOCALAPPDATA%\LiveSub\AI 助手\`）。文件名前面加日期和时间，同名时不会覆盖。回答里只显示“已保存：文件名”，点一下在资源管理器中选中这个文件。模型本身不能写文件，由 LiveSub 代为保存，而且只会存到这个文件夹。一次可以要求存多个文件。
  - 面板第一次打开时出现在字幕旁边：右边放不下就放左边；字幕在屏幕上半部分时顶边对齐，否则底边对齐。按住标题栏可以拖到别处，拖边框和四角可以改大小，位置和大小都会记住；字幕移动或改大小时面板不跟着动，设置里的“恢复默认”会把面板也放回字幕旁边。
  - 面板显示时不抢焦点，点输入框或对话内容时才激活面板、接收键盘输入；这时原来的程序失去键盘焦点（Windows 同一时间只有一个前台窗口，不会像 macOS 那样两处光标同时闪）。收起字幕时面板一起隐藏，字幕再显示时一起回来；每次启动程序时面板是关着的。
  - 用 Claude Code 时，面板打开后（或面板开着时开始字幕）另有一个 claude 进程，退出程序时结束。
- **生成笔记**（“字幕记录”窗口）：用 AI 助手的模型把本次全部字幕整理成 Markdown 笔记（总结、主要内容、关键术语、待办事项、可能识别错误的地方），保存在记录文件旁边，文件名为 `<时间> 笔记.md`（英文界面为 `<时间> Notes.md`），完成后用默认程序打开。进度和结果显示在字幕记录窗口底部的状态、托盘提示和托盘菜单顶部。
- **字幕记录窗口**（设置 › 记录 › 字幕记录 › 查看…，或托盘菜单 → 字幕记录…；改过）：与 macOS 版相同，列出本次全部字幕。每句上面一小行是时间（和音源、附注），下面是原文、纠正前的识别原文（打开“纠正时保留识别原文”并且改过时）和译文；文字可以选中复制。停在底部时跟着新字幕滚动，往上翻看时不打扰。下方显示当前状态，右边是“在资源管理器中显示记录”（有记录文件时打开文件夹并选中它，否则打开记录文件夹）、“导出字幕 ▾”（SRT / WebVTT）、“开始新的记录”和“生成笔记”（没有字幕时后三个不可点）。
- **记录**：每句实时写入 `文档\LiveSub\<时间> 字幕记录.md`，格式与 macOS 版相同（英文界面下文件名和文件头为英文：`<时间> Transcript.md`、“Started”“Language”和英文语言名）。没来得及翻译的句子在“开始新的记录”或退出时只写原文，不会丢句子。
- **导出字幕**（字幕记录窗口）：每句记录了它在音频里的起止时间（相对本次记录开始录音的时刻）；文字按当前显示内容（双语/仅译文/仅原文）。SRT 带 UTF-8 BOM，方便 Windows 播放器识别中文。
- **界面语言**：中文系统显示中文（简体），其他系统显示英文。测试时可以用环境变量 `LIVESUB_UI_LANGUAGE=en` 或 `zh-Hans` 指定。

### 隐私

- 语音识别完全在本机运行，音频不会上传。
- 识别出的文字会发送给你选择的翻译模型（Google 翻译、Claude Code，或所选的模型服务）；使用混元翻译、Ollama、LM Studio 时文字也留在本机。
- 向 AI 助手提问时，本次的字幕原文和你添加的附件（图片、文件）会发送给 AI 助手所选的模型；生成笔记时发送原文和译文。
- 录音只在你打开录音按钮时进行，保存在本机的记录文件夹里，不会上传。
- API 密钥用 Windows 数据保护（DPAPI，仅当前 Windows 用户可解密）加密，保存在 `%APPDATA%\LiveSub\secrets.bin`，不写入 `settings.json`，不写入日志。
- 设置：`%APPDATA%\LiveSub\settings.json`。日志：`%LOCALAPPDATA%\LiveSub\logs\livesub.log`，只记录事件和错误；设置环境变量 `LIVESUB_DEBUG_LATENCY=1` 时才会记录字幕文字（延迟分析用）。
- 记录文件和录音保存在本机 `文档\LiveSub`，不会上传。

### 已知限制

- **字幕比 macOS 版晚**：Whisper 不是流式识别，要等讲者停顿约 0.6 秒（或一段满 8 秒）才出确认结果。“实时预览”会先显示正在说的内容，但会多用处理器；机器较慢时程序会自动跳过预览。
- **没有 Apple 本地翻译兜底**：macOS 版的大模型出错时用 Apple 本地翻译顶上；Windows 版只有在用 Google 翻译、混元翻译、纠正用的 Claude 出错时，才用原来的翻译翻这一句，其他情况这一句显示“翻译失败”，状态条显示原因。
- **Google 翻译**是免费网页接口，没有官方保证，短时间请求太多可能被限流；需要联网。
- **混元翻译**在 Windows 上的速度没有实测（macOS 上每句约 0.3 秒）。没有显卡时用处理器，会慢一些。
- **过滤周围的中文交谈**（原来叫“过滤中文说话声”）：可选，Windows 版默认关闭（macOS 版默认开启）。打开后每段多做一次 Whisper 语言判断（只在“讲话语言 / 中文”之间判断），处理器开销约增加一半。
- **录音**用 Windows 自带的 AAC 编码器，最低 96 kbps（macOS 是 64 kbps），存成 48 kHz 单声道。Windows 的 N 版本没有这个编码器，要先安装“媒体功能包”，否则打开录音时提示“录音失败：这台电脑上没有 AAC 编码器……”，字幕照常。
- **外观**：设置、模型服务、字幕记录、录音记录窗口用 WPF 的 Fluent 主题（.NET 10 里仍标为实验性）做浅色和深色；弹出菜单（音源、模型菜单）和托盘菜单仍是系统的浅色样式。
- **AI 助手附件**：从浏览器拖图片请先保存或复制图片再粘贴：浏览器拖出来的常常只是“虚拟文件”，只有它同时提供了图片数据（PNG 或位图）时才能收下。旧的 .doc、PowerPoint、Excel 读不了，存成 PDF 或图片再添加。
- **自动纠正口音**：打开后才纠正。用 Whisper 的逐词概率判断“难识别”，阈值沿用 macOS（最近 60 个词平均低于 0.80 进入；高于 0.86 并且连续一分钟才退出，免得来回切换），但 Whisper 的概率刻度不同，可能需要按实测调整（日志里有平均置信度）。
- 音源为“两者”、两路同时有语音时，识别的工作量加倍：机器较慢时字幕会更晚，实时预览也更少出现。
- “本地模型”一组包括局域网里其他电脑上的服务（macOS 版只算本机）；这些地址也不要求填密钥。
- 中途换默认输出设备或默认录音设备（插耳机、蓝牙）时会自动重新开始采集；新设备连续 3 次打不开时停止字幕并说明原因（音源为“两者”时不停止：另一路照常，打不开的那一路之后每隔几秒重试）。采集中途意外断开时字幕不停，每隔几秒重新打开。需要实测。
- 麦克风降噪做哪些处理（降噪、回声消除、语音清晰度）由声卡驱动和 Windows 版本决定，有的电脑上打开后没有明显变化。
- “显卡加速”需要用 `-p:LiveSubGpu=vulkan` 或 `cuda` 构建；识别在下次开始字幕时按新设置，混元翻译在下一句时按新设置重启 llama-server。
- Claude Code 在 Windows 上可能要求安装 Git for Windows；未登录时字幕会提示登录。

### 测试清单

请在实体 Windows 电脑上逐项确认，记下结果（通过 / 不通过 + 现象）。日志在 `%LOCALAPPDATA%\LiveSub\logs\livesub.log`。

**安装与启动**

1. （改过）按“构建与运行”构建并启动：托盘出现图标，屏幕右上角出现字幕面板（新用户；用过的用户在原来的位置），中间是“开始翻译”按钮；面板不出现在任务栏和 Alt+Tab 里。
2. 再启动一次程序：不会出现第二个托盘图标，已运行的程序把字幕显示出来。

## English

LiveSub listens to **what your PC is playing** (videos, online classes, meetings), **your microphone** (lectures, conversations), or both at once, transcribes it locally, translates it with the model of your choice, and shows **floating bilingual subtitles**. It also saves a live transcript and exports SRT / WebVTT. While listening you can ask the **AI assistant** about what was said, and afterwards turn the subtitles into **notes**.

| Stage | Implementation | Notes |
|---|---|---|
| System audio | WASAPI loopback (NAudio) | No virtual audio device needed |
| Microphone | WASAPI capture (NAudio) | Capture restarts when the default recording device changes; optional noise reduction (Windows communications processing) |
| Speech recognition | Whisper.net (whisper.cpp), local | Model downloaded on first use; audio never leaves the PC |
| Translation | Google Translate (default), Hunyuan Translate downloaded to this PC, Claude Code CLI, or model services (OpenAI, Qwen, DeepSeek, Kimi and Grok are listed by default; you can add Anthropic, OpenAI-compatible APIs, local Ollama / LM Studio) | Switch any time |
| UI | WPF overlay + tray icon | Topmost, never steals focus, optional click-through; System / Light / Dark appearance |
| Recording | Media Foundation AAC (built into Windows) | Optional: saves what LiveSub hears as .m4a next to the transcript |

### Requirements

- Windows 10 or 11, 64-bit (x64).
- [.NET 10 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/10.0) (x64), unless you use a self-contained build.
- Recognition runs on the CPU; AVX2 CPUs are faster. The `base` model keeps up with normal speech on recent laptops.
- Internet access on first use to download the speech model (tiny ≈ 75 MB, base ≈ 142 MB, small ≈ 466 MB).
- Translation uses Google Translate by default, with no account or setup (internet required). Alternatives: Hunyuan Translate, downloaded in Model Services (about 1.2 GB, about 1.4 GB of memory while running) and run offline on this PC; a signed-in Claude Code CLI; your own API key for one of the listed services (OpenAI, Qwen, DeepSeek, Kimi, Grok) or one you add (Anthropic, Gemini, OpenRouter, …); or a local Ollama / LM Studio.
- The AI assistant, notes and accented-speech correction need a language model (Claude Code or a model service); Google Translate and Hunyuan Translate can only translate.

### Build and run

Requires the [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0). From the `windows` folder:

```powershell
dotnet build LiveSub.Windows.sln -c Release
dotnet test tests/LiveSub.Core.Tests                 # unit tests (platform-independent; also run on macOS)
dotnet run --project src/LiveSub.App -c Release

# Self-contained build: no .NET install needed on the target PC; produces publish\LiveSub.exe
dotnet publish src/LiveSub.App -c Release -r win-x64 --self-contained -o publish

# Optional GPU runtime (larger; enable "GPU Acceleration" in Settings)
dotnet publish src/LiveSub.App -c Release -r win-x64 --self-contained -p:LiveSubGpu=vulkan -o publish-vulkan
# NVIDIA: -p:LiveSubGpu=cuda (requires a matching CUDA runtime)
```

The executable is not code-signed; SmartScreen may warn about an unknown publisher on first launch.

### First run

1. Start `LiveSub.exe`. A subtitle icon appears in the notification area (possibly under “^”), and the overlay appears in the top-right corner of the screen with a Start Translating button in the middle. New users start with the audio source set to Both (microphone and system audio at once); change it from the quick buttons' audio source menu or in Settings.
2. Google Translate is the default translation model and needs no setup. To switch, click the Settings quick button on the overlay (or right-click the tray icon → **Settings…**) and choose a **Translation Model**: Claude Code needs nothing else; for a listed service such as OpenAI or Qwen, click **Manage…** next to Model Services, enter your API key and click **Test**; Hunyuan Translate must be downloaded in Model Services first (below).
3. Click **Start Translating** in the middle of the overlay (or right-click → **Start Subtitles**). The first start downloads the speech model with progress shown below the button, into `%LOCALAPPDATA%\LiveSub\models`. If huggingface.co is unreachable, set a mirror under Settings → Recognition → **Model Download Host**, or copy `ggml-base.bin` into that folder.

### Translation models and model services

As on macOS, Settings → **Translation Model** has three groups; the tray menu and the status bar (click the model name) switch models too, and both end with “Manage Model Services…”.

- **Basic**: Google Translate (the default for new users; existing users keep their choice).
- **Cloud Models**: Claude and each cloud model service.
- **Local Models**: Hunyuan Translate (downloaded to this PC) and services on this PC or the local network (Ollama, LM Studio, …).

**Each service is listed once** (menus show service names such as “Claude” or “Qwen”); which of its models to use is chosen in Model Services, separately **For Translation** and **For AI Assistant**. Claude uses Haiku for translation and Sonnet for the assistant by default. Changing a service's model for translation switches a translation that uses that service; the same goes for the assistant. The log, status and notes progress show full names such as “Claude · Haiku”, “Qwen · qwen-flash” or “Hunyuan Translate · Hy-MT2 1.8B”. When upgrading, a specific model picked from the old list (for example Claude Opus, or one model of a service) becomes Claude's or that service's model for translation or the assistant, so you keep using it.

**Google Translate** (free web endpoints, no key), as on macOS: two endpoints (gtx on `translate.googleapis.com` and dict-chrome-ex on `clients5.google.com`) rotate. When one is rate-limited (HTTP 429 or a server error) the other is used and the limited one cools down for 60 s; when both fail, LiveSub waits 1–4 s and tries each once more before giving up on the line. Each line is translated on its own, without context. Google Translate and Hunyuan Translate translate two lines at once; language models keep context and go one line at a time. For testing, `LIVESUB_DEBUG_GOOGLE_FAIL=gtx` (or `dictionaryExtension`, `all`) pretends that endpoint is rate-limited.

**Hunyuan Translate** (Tencent Hunyuan Hy-MT2 1.8B, offline on this PC): in Model Services → “Hunyuan Translate · On This PC”, **Download** first fetches the llama.cpp runtime (pinned to b11829; on x64 the Vulkan build `llama-b11829-bin-win-vulkan-x64.zip`, about 37 MB, which can use the GPU and also includes CPU backends; on ARM64 `llama-b11829-bin-win-cpu-arm64.zip`, about 13 MB), then the model `Hy-MT2-1.8B-Q4_K_M.gguf` (1,133,080,448 bytes). Both are checked against SHA-256 and deleted with an error if they don't match; downloads can be cancelled and retried. The model comes from Settings → Recognition → Model Download Host (if set), then Hugging Face, then hf-mirror.com. Files live in `%LOCALAPPDATA%\LiveSub\LocalModel\`; **Delete** removes the folder and switches a translation that uses it back to Google Translate. While translating, LiveSub runs `llama-server` in the background (no console window, listening only on a random free port on 127.0.0.1, same arguments as macOS: `-c 4096 -np 2 --jinja --no-webui -ngl 99`, or `-ngl 0` with GPU Acceleration off) and waits up to 90 s for the model to load. It stops when no translator uses it, after 10 idle minutes and on quit; if LiveSub crashes, the Windows job object (as for claude) ends it too. Its output goes to `%LOCALAPPDATA%\LiveSub\logs\llama-server.log`. Prompts and sampling (temperature 0.7, top_p 0.6, top_k 20, repeat_penalty 1.05) match macOS; each line carries the previous two source lines as background. Test times exclude starting the server and loading the model. If Hunyuan Translate is selected but not downloaded when subtitles start, the overlay says so, Model Services opens at that section and Google Translate is used for now; once the download finishes, running subtitles switch to Hunyuan Translate. llama-server needs the Microsoft Visual C++ runtime (Whisper needs it too, so it is normally present); LiveSub explains when it is missing.

**Claude Code CLI** — uses your Claude Code subscription, exactly like the macOS app. Install Claude Code (`irm https://claude.ai/install.ps1 | iex` or npm), run `claude` once and `/login`. In Model Services → Claude Code choose the model For Translation and For AI Assistant: Haiku (fastest), Sonnet (balanced) or Opus (most accurate, slowest). **Claude Path** moved there too (it used to be in Settings); when empty, LiveSub finds `claude` on PATH, in `%USERPROFILE%\.local\bin\claude.exe` or `%APPDATA%\npm\claude.cmd` (npm shims are run through node directly so the multi-line system prompt survives). **Test** translates one sentence with the translation model. One long-lived `claude -p --input-format stream-json …` process with the same arguments and environment as macOS; a fresh process every 40 lines, seeded with the last 6 lines.

**Model services** — Settings → Model Services → **Manage…** (also **Manage Model Services…** at the end of the tray and status-bar model menus). The window lists Claude Code, Hunyuan Translate and then each service.

- **Listed by default**: OpenAI (gpt-5.4-mini), Qwen (qwen-flash), DeepSeek (deepseek-flash), Kimi (kimi-k2.6) and Grok (grok-4.20-0309-non-reasoning) already appear under translation models and the AI assistant; add your own API key to use them. They have the same fixed IDs as on macOS and missing ones are added at every launch, except those you deleted (you can add them back from Add Model Service) and those whose address you already added yourself. Choosing one without a key opens Model Services at that service and explains where to get a key.
- Each service has a name, API format, base URL, API key, **Available Models** (**Fetch List**, then remove the ones you don't need; comma-separated), **For Translation**, **For AI Assistant**, **Test** (translates one sentence with the translation model and shows “X works, N s: …”) and Delete. Deleting a service also deletes its key; a translation that used it switches back to Google Translate and the assistant back to Claude.
- Thinking is turned off where supported: DeepSeek and Kimi (only kimi-k2.6 allows it) get `thinking: {type: disabled}`, Qwen gets `enable_thinking: false`, and no other service gets either (OpenAI rejects unknown parameters with HTTP 400).
- Templates in Add Model Service: OpenAI `https://api.openai.com/v1`, Qwen (DashScope compatible mode) `https://dashscope.aliyuncs.com/compatible-mode/v1`, DeepSeek `https://api.deepseek.com`, Kimi `https://api.moonshot.cn/v1`, Grok `https://api.x.ai/v1`, Anthropic (Anthropic format, `https://api.anthropic.com`), Gemini `https://generativelanguage.googleapis.com/v1beta/openai`, OpenRouter `https://openrouter.ai/api/v1`, Ollama `http://localhost:11434/v1`, LM Studio `http://localhost:1234/v1`, or Custom. Local and LAN addresses need no key.
- OpenAI-compatible: `POST {base}/chat/completions` (streaming), models from `GET {base}/models`. Reasoning models add latency; prefer non-reasoning models for subtitles.
- Anthropic: the official C# SDK, `POST {base}/v1/messages`, models from `GET {base}/v1/models`. For low latency, Haiku runs with thinking disabled; Sonnet and Opus cannot disable thinking, so they run with effort = low; models not named `claude-…` get neither setting.
- Upgrading from Windows 0.1: the Anthropic API settings become a model service named “Anthropic”, and each OpenAI-compatible service becomes a model service with the same name; keys and the selected model are kept.

All language models share the macOS prompts, the `[Context]…[Translate]` context format and the output sanitizer. Sentence splitting matches macOS: a long run without sentence punctuation is cut at a clause boundary (comma etc.) once it exceeds 24 units (words; two CJK characters count as one), and text flushed after a pause is split the same way.

### Usage

- **Overlay** (changed): for new users the subtitles sit in the top-right corner of the screen, covering 1/16 of the screen at a 3:1 aspect ratio (as on macOS; existing users keep their size and position). Before you start, a prominent **Start Translating** button sits in the middle, with the audio source and languages below it (the reason after a failed start, or the speech-model download progress while preparing); earlier lines are dimmed behind it. Drag to move. The window size changes only with settings, never with the text: new lines scroll up inside it. Drag the left/right edges to change the width and the top/bottom edges to set your own height; double-click the top/bottom edge to go back to the height from Lines Shown (one source line plus one translation line each, plus the live line). When a setting such as the font size makes the window taller, the bottom edge stays put and the window grows upward, and it is pushed back onto the screen if it would leave it. Scroll up to read earlier lines; a thin position bar and “Back to Live” appear.
  - **Quick buttons** (changed, as on macOS): hovering shows seven buttons: Start/Stop, Record, Lock, Audio Source (a menu: Microphone / System Audio / Microphone and System Audio, current one checked), AI Assistant (yellow while open; orange in the light appearance), Settings and Quit. Hovering a button **immediately** shows its name below it (no system tooltip delay), and the name follows the state (Start → Stop, Record → Stop Recording). The overlay always stays on top; there is no “keep on top” switch. The “⋯” menu and the Hide button are gone: the display mode is in Settings, the transcript is in Settings › Transcripts and the tray menu, hide the overlay with the shortcut or the tray menu, and “Move Subtitles to Bottom” became Reset in Settings.
  - **Live line**: speech that is not yet a full sentence appears in one fixed italic line below the subtitles. When it is longer than the line, only the newest words are shown after a leading “…” (spaced languages are cut between words). The line keeps its height when empty, so the subtitles above never jump. With the audio source set to Both and both sides speaking, there are two lines, each with its source tag; the window keeps its height and the subtitle area above gives up one line.
- **Appearance** (new, Settings › Subtitles › Appearance): System (default), Light or Dark, as on macOS. Dark is white on black; light is black on white with a faint outline. The overlay, the AI assistant and the Settings, Model Services, Transcript and Recordings windows change together. System follows Windows Settings › Personalization › Colors › “Choose your default app mode” and updates as soon as it changes. The settings-type windows use WPF's built-in Windows 11 style theme (Fluent); pop-up menus and the tray menu keep the light system style.
- **Recording** (new, as on macOS): the Record quick button (or Record in the tray menu) saves what LiveSub hears into the transcript folder while subtitles run. The file is named after the transcript with “Transcript” replaced by “Recording”, e.g. `2026-10-22 13.35 Recording.m4a` (`… 录音.m4a` under the Chinese UI); with the source set to Both there is one file per source, e.g. `… Recording (Microphone).m4a`; a number is added instead of overwriting. It can be turned on or off at any time while running; when subtitles are stopped the button only remembers the choice for the next start. While recording the button is red and the status bar shows a red “Recording”. The format is AAC (.m4a) from the Media Foundation encoder built into Windows, 48 kHz mono at about 96 kbps (Windows' AAC encoder starts at 96 kbps; macOS uses 64 kbps), about 43 MB per hour. The recording stays aligned with real time (silence is filled in when nothing plays). ### Privacy

- Speech recognition runs entirely on your PC; audio is never uploaded.
- Recognized text is sent to the translation model you choose (Google Translate, Claude Code or the selected model service); with Hunyuan Translate, Ollama or LM Studio it stays on your PC.
- When you ask the AI assistant, this session's source text and any attachments you add (images, files) are sent to the assistant's model; Generate Notes sends source text and translations.
- Recording happens only while the Record button is on; recordings stay in your transcript folder and are never uploaded.
- API keys are encrypted with Windows Data Protection (DPAPI, current user only) in `%APPDATA%\LiveSub\secrets.bin`, never written to `settings.json` or the log.
- Settings: `%APPDATA%\LiveSub\settings.json`. Log: `%LOCALAPPDATA%\LiveSub\logs\livesub.log` (events and errors; subtitle text only when `LIVESUB_DEBUG_LATENCY=1`).

### Known limitations

- Subtitles arrive later than on macOS: Whisper is not streaming, so a segment is recognized after a ~0.6 s pause or 8 s of continuous speech. Live Preview shows a draft of the current segment at extra CPU cost and is skipped automatically on slow machines.
- No Apple Translation fallback (macOS falls back to it when a language model fails). Windows falls back only when Claude, correcting for Google Translate or Hunyuan Translate, fails: that line uses the original translator. Otherwise the line shows “Translation failed” and the status bar shows why.
- Google Translate uses free web endpoints with no official guarantee and may be rate-limited under heavy use; it needs internet access.
- Hunyuan Translate's speed on Windows has not been measured yet (about 0.3 s per line on macOS); without a usable GPU it runs on the CPU and is slower.
- Filter Nearby Chinese Conversation (formerly Filter Chinese Speech) is optional and off by default on Windows (on by default on macOS); it adds one Whisper language check per segment (limited to the spoken language vs. Chinese).
- Recording uses the AAC encoder built into Windows, which starts at 96 kbps (macOS uses 64 kbps), and saves 48 kHz mono. Windows N editions lack it until the Media Feature Pack is installed; turning recording on then shows “Recording failed: This PC has no AAC encoder…” and subtitles carry on.
- Appearance: the Settings, Model Services, Transcript and Recordings windows use WPF's Fluent theme (still marked experimental in .NET 10) for light and dark; pop-up menus (audio source, model menus) and the tray menu keep the light system style.
- Assistant attachments: to use an image from a browser, save or copy it first and then paste; browsers often drag only a “virtual file”, which is accepted only when the image data (PNG or bitmap) comes along. Old .doc, PowerPoint and Excel files cannot be read; save them as PDF or images.
- Auto-correction runs only when turned on. It uses Whisper token probabilities with the macOS thresholds (enter when the last 60 words average below 0.80; leave only after staying above 0.86 for a full minute, to avoid flip-flopping); Whisper's scale differs, so the thresholds may need calibration (the log records the average confidence).
- With the source set to Both and speech on both sides, recognition does twice the work: on slower PCs subtitles arrive later and live previews appear less often.
- **Local Models** also include services on other computers in the local network (macOS counts only this computer); they need no key either.
- When the default output or recording device changes, capture restarts automatically; if the new device fails to open three times, subtitles stop with the reason shown (with the source set to Both they keep running: the other source continues and the failed one is retried every few seconds). If capture drops unexpectedly, subtitles keep running and capture is reopened every few seconds.
- Which processing Microphone Noise Reduction applies (noise suppression, echo cancellation, Voice Clarity) depends on the audio driver and Windows version; on some PCs it makes little difference.
- GPU acceleration requires a `-p:LiveSubGpu=vulkan` or `cuda` build; recognition picks up a change at the next Start, and Hunyuan Translate restarts llama-server with the new setting at the next line.
- Claude Code on Windows may require Git for Windows.
